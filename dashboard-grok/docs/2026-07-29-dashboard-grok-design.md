## 1. Goal

A **client-only**, light-theme dashboard that visualizes QQQ trading signals under `input/` (**read-only**), compares each signal to the matching QQQ session move, and ranks every **folder/model** (project-wide, ~12 columns) by accuracy and magnitude-weighted score. All generated artifacts and tooling live under `dashboard-grok/`.

## 2. Decisions (locked)

| Topic | Choice |
|--------|--------|
| Architecture | Everything under `dashboard-grok/`; `input/` is read-only prediction source |
| Prediction discovery | `dashboard-grok/manifest.json` listing paths under `input/` |
| Manifest updates | GitHub Action regenerates files **inside** `dashboard-grok/` when `input/` changes |
| QQQ prices | Live Yahoo + `dashboard-grok/qqq-ohlc.json` cache |
| Layout | Flat project-wide board (not 3 engine silos); heatmap with ~12 folder/model columns |
| Neutral band | If `\|session return\| < 0.01%` → neutral (not correct/wrong; no weight) |
| Theme | Background `#FAFAFA`, accent `#16A34A`, font **Lora** (OFL via Google Fonts) |

## 3. Data sources

### 3.1 Predictions

Path pattern:

```text
input/{engine}/{model}/{YYYYMMDD}_QQQ_{session}_{modelOrAlias}_{timestamp}.json
```

Current engines (folders):

- `news-trader-ppx-live`
- `news-trader-llm-live`
- `news-trader-crash-live`

JSON schema (uniform today):

```json
{
  "date": "2026-07-28",
  "symbol": "QQQ",
  "session": "pre-market" | "intraday",
  "signal": "HOLD" | "SELL",
  "confidence": 0.72,
  "threat_level": "HIGH" | "MODERATE" | "...",
  "key_catalyst": "...",
  "reasoning": "..."
}
```

**Deduping:** For each `(engine, model, date, session)`, keep the file with the **latest timestamp** suffix in the filename.

**Column identity:** `engine/model` (e.g. `news-trader-llm-live/cursor-claude-opus-4-8`). Column count is dynamic from the manifest (today ≈ 12).

### 3.2 Manifest

- File: `dashboard-grok/manifest.json`
- Generated by `dashboard-grok/scripts/generate-input-manifest.py` (also run in CI)
- Scans `input/**/*.json` **read-only**; never writes under `input/`
- Shape:

```json
{
  "generated_at": "ISO-8601",
  "files": [
    "input/news-trader-ppx-live/claude-opus-4-8/20260728_QQQ_pre-market_....json"
  ]
}
```

Exclude accidental `manifest.json` / `qqq-ohlc.json` under `input/` from the scan. Paths are relative to site/repo root.

### 3.3 GitHub Action

- Trigger: `push` paths under `input/**` (and optionally manual `workflow_dispatch`)
- Steps: checkout → run generate script → if `manifest.json` changed, commit + push with a bot message
- Guard: skip commit loops (only commit when content differs; Action should not infinite-loop on its own commit — e.g. `[skip ci]` or path filters that ignore manifest-only commits from the bot, **or** regenerate only when non-manifest input files change)

Recommended: Action commits only under `dashboard-grok/`, so it never modifies `input/`.

### 3.4 QQQ OHLC (Yahoo)

- Fetch daily OHLC for QQQ covering prediction date range + enough forward days for overnight evaluation
- Endpoint (client): Yahoo chart API for symbol `QQQ`, interval `1d`
- Use a CORS-friendly path if direct Yahoo blocks browsers (e.g. public CORS proxy only if required; prefer direct first, document fallback)
- Build a map: trading date → `{ open, close }`
- Non-trading days: skip; “next open” = next available trading day in the series

## 4. Session return mapping

| Signal session | Compared QQQ move | Formula |
|----------------|-------------------|---------|
| `pre-market` on date D | Regular session open → close on D | `r = (close_D - open_D) / open_D` |
| `intraday` on date D | Close D → next trading day open | `r = (open_next - close_D) / close_D` |

- **Pending:** required price not available yet → UI shows pending; excluded from accuracy and weight
- Returns expressed in percent for display (e.g. `+1.25%`)

## 5. Scoring

### 5.1 Direction

Given session return `r` (fraction):

1. If `|r| * 100 < 0.01` → **neutral**
2. Else if `r > 0` → **rise**
3. Else → **drop**

### 5.2 Correctness

| Signal | Rise | Drop | Neutral / pending |
|--------|------|------|-------------------|
| HOLD | correct | wrong | excluded |
| SELL | wrong | correct | excluded |

### 5.3 Weight score

For each scored prediction with return `r` (fraction):

- Correct → `+|r| * 100` (percent points)
- Wrong → `−|r| * 100`
- Neutral / pending → `0` (not added)

Examples: HOLD + session +2.0% → **+2.0**; HOLD + session +0.5% → **+0.5**; SELL + session −1.2% → **+1.2**; wrong on ±2% move → **−2.0**.

**Per column (folder/model):**

- `weight_total` = sum of per-prediction weights
- `accuracy_all` = correct / scored (all signals)
- `accuracy_hold` / `accuracy_sell` = same split by signal
- Optional: also by session (`pre-market` / `intraday`)

### 5.4 Rank

- Primary sort: `weight_total` descending
- Tie-break: `accuracy_all` descending, then scored count descending, then column name ascending
- Rank is **project-wide across all folder/model columns** (not per-engine silos)
- Secondary mini-ranks may filter to pre-market-only or intraday-only weights

## 6. UI structure

Light theme, airy “fresh air” aesthetic: soft mint/sky/warm wash gradients, teal accent, expressive display font (not Inter/Roboto/Arial). Avoid purple-glow / dark-mode defaults. Mobile-usable horizontal scroll for wide tables.

### 6.1 Page sections (top → bottom)

1. **Header** — brand “Signal Arena” (or similar), last-loaded timestamp, short QQQ range status
2. **Leaderboard** — ranked list of all folder/model columns with weight, overall accuracy, HOLD/SELL accuracy, scored count
3. **Accuracy summary table** — rows = folder/model; columns = All / HOLD / SELL (correct, n, %); filters or sub-rows for session optional
4. **Heatmap** — primary visualization (see §6.2)
5. **Date detail** — date picker/chips; for selected date, two panels:
   - **Pre-market:** QQQ open→close move + each model’s signal, confidence, catalyst snippet, correct/wrong/pending
   - **Intraday:** QQQ close→next open move + same per-model breakdown
6. **Footer note** — scoring rules one-liner + “manifest generated by CI”

### 6.2 Heatmap

- **X axis:** every `folder/model` column (~12 today), order = leaderboard rank (best left → worst right) or stable alphabetical within engine — **use leaderboard rank order** so reading left-to-right matches strength
- **Y axis:** each `date · session` row, chronological (newest at top or oldest at top — **newest at top**)
- **Bottom row:** **Overall** — sum of weights across all scored rows for that column
- **Cell content:** signed weight for that prediction (e.g. `+0.82`, `−1.10`), or `—` / empty for missing/pending/neutral
- **Cell color:** diverging scale (green positive, red negative, muted zero/neutral/pending)
- **Medals (per row, including Overall):** among columns on that row with a scored (non-neutral) weight, highest → 🥇, second → 🥈, third → 🥉
  - If fewer than 3 scored cells in a row, only award available places
  - Ties: higher confidence wins; then earlier column name
- Wide grid: horizontal scroll on small screens; sticky first column (date/session label) and sticky header row

### 6.3 Motion (wow, light)

At least 2–3 intentional motions:

1. Staggered fade/rise of leaderboard rows on load
2. Heatmap cells fade-in or subtle value count-up for Overall row
3. Soft highlight pulse on 🥇 cells (not neon glow spam)

## 7. Runtime flow

```text
Page load
  → fetch dashboard-grok/manifest.json
  → fetch prediction JSONs under input/ (read-only)
  → dedupe to latest per (engine, model, date, session)
  → fetch Yahoo QQQ daily OHLC (fallback dashboard-grok/qqq-ohlc.json)
  → compute returns, correctness, weights
  → render leaderboard, accuracy table, heatmap, date detail
```

Errors:

- Manifest missing → clear empty state: “Run manifest Action / generate script”
- Yahoo failure → show banner; still list signals without scores
- Partial prediction fetch failures → skip bad files, show count of loaded vs listed

## 9. Operator workflow

1. Add/update prediction JSON files under `input/{engine}/{model}/`
2. Commit + push to GitHub
3. Action regenerates `dashboard-grok/manifest.json` (+ OHLC cache) and commits those only
4. Open / refresh `https://ncelq.github.io/dashboard-grok/` → latest data + live QQQ prices

Local optional: `python dashboard-grok/scripts/generate-input-manifest.py` before push if previewing without waiting for CI.

## 10. Acceptance checks

- Refresh after new predictions (and Action-updated manifest) shows new rows/columns without editing the HTML
- Pre-market rows use open→close; intraday rows use close→next open
- HOLD+rise and SELL+drop mark correct; opposites wrong; `|r|<0.01%` neutral
- Weight rewards larger correct moves and penalizes larger wrong moves
- Heatmap has one column per folder/model, medals 🥇🥈🥉 per row, Overall bottom row
- Leaderboard ranks all columns project-wide by weight
- Light theme, readable on desktop and mobile (tables scroll)

## 11. Open implementation notes (non-blocking)

- Yahoo CORS: implement direct fetch first; if blocked in browsers, use a documented fallback (e.g. `query1.finance.yahoo.com` via a tiny static mirror only if required — prefer no backend)
- Exact brand title string can be finalized at implement time (“Signal Arena” working title)
- Chart.js optional for date-detail spark/bars; heatmap can be pure HTML/CSS table for clarity and medal glyphs
